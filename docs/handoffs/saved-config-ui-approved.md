# 保存处理配置：UI 方案（Owner 已批准）

依据 Antigravity 本次真实 CLI 返回，由 Codex 做范围/可实现性核对后整理。本文件保留开发前批准的界面方案；实际 WPF 实现与桌面 QA 状态统一见 `issue56-verification.md`。

## 入口

- 格式统一：右侧“整批共用规则”卡片顶部。
- 数据匹配：右侧“返回字段与选项”卡片顶部；配置涵盖该页匹配条件及选项，不只作用于返回字段。
- 配置类型由当前页面固定，不增加第三页或管理中心。列表只包含用户自己保存的配置，没有内置预设、默认模板或云端内容。

采用两行紧凑布局，避免把下拉框和三个按钮挤在格式统一的窄侧栏中。控件保持现有样式和至少 32 DIP 高度；内容区继续局部滚动，固定执行底栏不变。窗口仍支持 960×640 最小尺寸。

```text
格式统一 / 整批共用规则        数据匹配 / 返回字段与选项
┌──────────────────────┐     ┌──────────────────────────┐
│ 处理配置              │     │ 处理配置                  │
│ [月度清理配置      ▾]  │     │ [科室月报匹配          ▾] │
│ [应用] [保存配置…] [删除]│   │ [应用] [保存配置…] [删除] │
│ 已应用：月度清理配置    │     │ 已应用：科室月报匹配      │
├──────────────────────┤     ├──────────────────────────┤
│ 原有六项规则及保护说明  │     │ 原有字段搜索、多选、筛选、 │
│ …（局部滚动）          │     │ 比较/状态选项（局部滚动）  │
└──────────────────────┘     └──────────────────────────┘

下方保留原有输出设置、开始按钮、结果及真实进度。
```

该图表达控件分组和位置，不锁定字符宽度；实际 WPF 必须验证最小窗口可达性。

## 交互

1. **保存**：点击“保存配置…”打开轻量模态命名框，提示“保存当前格式统一规则”或“保存当前匹配设置”。空名称不可保存；同一功能已有该名称时明确确认覆盖。确认框取消或 Esc 返回页面，页面和旧配置均不变。更换名称即可另存。
2. **选择**：下拉只选择一个保存项，不立即修改页面。首次为空时显示“暂无保存配置”，“应用/删除”禁用；保存有效当前设置仍可用。
3. **应用**：点击后校验并显示“正在校验配置…”。格式配置恢复六项规则；匹配配置先核对当前双表预览与实际筛选候选。全部通过才更新页面，并显示“已应用：名称”。不自动开始，不改输出路径。
4. **失败**：就地提示原因，例如“未应用：对照表 C 列原为‘金额’，当前为‘数量’”或“未应用：新主表筛选列中不存在保存值”。保持当前设置。具体错误可以在原有受限高度错误区完整查看，不把执行底栏挤走。
5. **修改**：应用后仍能手动修改条件/规则；不自动覆盖已保存配置。修改后原“已应用”提示应改为“当前设置已修改”，避免暗示当前页面仍与保存项完全一致。
6. **删除**：确认框显示配置名；确认只删除保存项，不删除输入/输出文件、不清空已应用到页面的设置。不自动选中或应用另一个配置。取消保持原状。
7. **状态约束**：处理中禁用全部配置操作；应用/校验期间禁止并发开始与冲突操作。输入或配置代次改变，过时响应丢弃。处理、读取或写入失败后按钮恢复到符合当前有效性的状态。
8. **键盘**：下拉、按钮、命名框纳入 Tab 顺序；Enter/Space 按控件语义触发，Esc 取消弹窗；模态框关闭后焦点回到触发按钮。沿用既有可见焦点和按下反馈。

## 对原始提案的修订

- 去掉“预设与自定义配置”“重置为默认”等未经用户选择的能力；首次无保存项就是空列表。
- 原单行下拉加三个按钮在窄规则栏可能放不下，改为两行，保留尺寸与滚动基线。这是本次待审批方案的一部分，未修改已批准的 UI。
- “另存”统一为“保存配置…”，同名时明确覆盖，减少首次使用歧义。
- 命名框明确使用模态流程，不保留“行内或非模态”的未定分支；删除不恢复默认业务设置。
- 所有可选规则关闭不能保存（仍可手动全部关闭，原有开始限制不变）；错误/未知版本的配置不能绕过校验。
