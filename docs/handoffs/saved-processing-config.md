# 保存处理配置：Gate 1 确认包

版本：Owner 于 2026-09-09 在本任务回复“批准”，确认本包、UI 方案及本功能合成样例 GUI 自动化验收。基线 `9b608adea1fe6f1a79b14ec7a58dc476605fcaf7`。本包不批准 commit、push、merge 或 release。

## Requirements

R1. 在现有“格式统一”和“数据匹配”中分别提供本机命名配置。用户把当前设置保存一次，重启或换文件后主动选择并应用，减少重复勾选。不会启动时自动恢复或自动处理文件。

R2. 格式统一配置保存六个可选开关：首尾空白清理、制表符/换行/隐藏字符清理、全半角统一、Unicode 统一、安全数字统一、无歧义日期统一。应用到整批共用规则；至少选择一项才可保存和开始。前导零、长数字和公式保护沿用现有行为。

R3. 数据匹配配置保存：按当前顺序排列的 AND 匹配条件、返回字段选择、比较标准化开关、状态列开关/列名、主表筛选开关/列/实际选中值。筛选值保存原类型，不仅保存显示文字。必须有有效的当前双表预览、完整条件、至少一个返回字段以及有效筛选（若启用），才能保存；不要求先生成结果文件。

R4. 每页只列出自己的配置。支持“保存配置…”、选择后“应用”、确认后“删除”；同名保存先确认覆盖，取消则保留旧配置。名称去除首尾空白后不能为空，同一功能内大小写不区分地检查重名。更换名称保存可另存一份，不增加专门的重命名流程。

R5. 数据匹配先选新文件、工作表、表头行，再应用配置。按配置涉及列的“物理列号＋原始表头”核对新预览：列缺失、移动、改名或表头变空时整体不应用，列出预期字段与当前字段，并保留当前页面设置。重复表头仍按列号区分；不按同名列自动猜测重映射。未使用的列变化不阻止复用。

R6. 启用筛选的配置须重新读取新主表所选列的全部候选，按类型和值核对。保存值不存在、类型不匹配或候选读取失败时，整体不应用并显示原因，不自动关闭筛选或套用旧候选。全部检查通过后一次性应用；应用不启动处理。

R7. 配置保存成功、失败及应用结果明确可见。应用后手动更改规则/条件/选项时，提示从“已应用：名称”改为“当前设置已修改”，不会自动覆盖保存项。删除配置不清空已经应用到页面的设置。保存失败保留旧配置；配置文件损坏或版本不支持时不应用，保留当前页面设置。处理中禁用配置操作；加载/校验时阻止冲突操作及开始，过时异步结果不能覆盖新的文件或设置。

R8. UI 仅在两个现有页面的规则/选项卡片顶部增加两行紧凑配置入口：第一行为配置选择，第二行为应用/保存/删除按钮。原规则或字段区的可见高度会相应减少，超出部分局部滚动；不改变固定执行底栏、最高96 DIP的错误区和960×640最小窗口。详细交互见同目录 `saved-config-ui-approved.md`；审批本条也包含接受该空间调整。原有字段显示和处理结果不变。

## Scope

**In Scope**：上述两种配置的本机保存/管理/主动应用；相关列校验、筛选候选复核；最小 WPF 入口及状态提示；配置数据结构、存储和调用契约；对应自动化测试、桌面功能测试及文档。功能生效仅面向已支持的 `.xlsx`、`.xls`、`.csv`。

**Out of Scope**：不保存输入/输出路径、文件名、整表数据、批量清单、Sheet 选择、表头行、覆盖输出许可、预览、候选列表或执行结果。当前已选筛选字面值属于配置，会保存。输出目录继续使用现有记忆功能。不提供导入导出、跨电脑分享、云同步、自动执行、定时执行、智能列映射、新匹配算法、批量匹配或新增文件格式。

**分工与顺序**：Grok Build 负责正式需求、一个 Feature Issue 和范围审查；Codex 负责模型、存储/校验与测试；Antigravity 负责 UI 规格和 WPF 集成；服务边界与调用顺序双方会签后实现。Codex 负责派发、收取结果和验证。正式 Issue 与仓库文档在本包确认后由 Agent 衔接，用户不负责复制消息或写评论。

**本次桌面验收授权（Owner 已批准）**：为了让 Agent 执行 FT17 及相关实际窗口操作，本功能临时允许桌面 GUI 自动化：启动本功能测试版，操作窗口、键盘和原生对话框，只读写专门目录内的合成样例、测试配置及测试输出；通过注入/测试构建重定向配置存储，不覆盖用户现有配置。改变应用窗口尺寸，但不修改全局 DPI、安装设置或其他应用数据。保留截图及操作/结果记录，与 Core/组件测试分开报告。当前 `AGENTS.md` 的“不启用桌面 GUI 自动化”仍有效；本次批准只覆盖本功能测试，不改变永久规则。

## Acceptance Criteria

| ID | 验收标准 |
| --- | --- |
| AC01 | 两类配置各自保存、列出和应用，重启后仍可使用；空名称/同名/取消/删除反馈明确；同一功能内仅大小写不同的名称也须确认覆盖。 |
| AC02 | 保存内容完整覆盖 R2/R3；不存在源文件路径、输出许可、整表数据等禁止保存项；六个可选规则全关闭时不能保存格式配置。 |
| AC03 | 格式配置应用到全部待处理文件的共用规则，未应用配置时仍为既有默认规则。 |
| AC04 | 换文件后结构兼容的匹配配置正确恢复所有条件、返回字段、选项及筛选；执行结果与手动设置相同。 |
| AC05 | 缺失/移动/改名/空表头的引用列明确拒绝应用；重复表头不误映射；无关列变化仍可复用。 |
| AC06 | 筛选值使用当前新文件候选及完整类型核验；缺值/类型冲突/读取失败不产生半套配置。 |
| AC07 | 保存/应用不会自动处理文件；应用不改变当前文件/Sheet/表头/输出配置，不绕过覆盖确认和输入保护。 |
| AC08 | 损坏/未知版本/写入失败/用户取消不损坏旧配置、不改动源文件，页面可恢复操作；删除保存项不清空当前页面设置。 |
| AC09 | 校验期间不重复开始；旧异步返回不覆盖新状态；处理中所有配置操作禁用。 |
| AC10 | 两页入口和提示在最小及基准窗口可达，键盘操作有效；应用后修改显示“当前设置已修改”，不自动覆盖保存项；原有主路径与失败重试回归通过。 |
| AC11 | 相关 build/test、实际 UI Functional QA 与回归都有可追溯证据；未执行项不得写 PASS，不以组件或 Core 测试代替桌面 QA。 |
