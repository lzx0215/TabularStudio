# 处理规则

- Status: Skeleton
- Owner: **Codex**
- Approver: Project Owner
- Reviewer for scope: Grok
- Related: `docs/requirements.md`、`docs/contracts.md`

## 文档用途

记录格式统一、数据匹配的已确认业务处理规则。这是 Core 实现与测试的行为依据。

**Grok 不在本文设计算法或 Excel 细节。**  
**Antigravity 不在本文改处理规则。**

## 约束

- 库：ClosedXML
- 主格式：`.xlsx`
- 运行：完全离线、本地文件
- 只覆盖 MVP 两个功能
- 规则必须能追溯到 `docs/requirements.md`
- 不得把未确认规则写进代码

## 待 Owner 回填

Codex 回填时只整理已确认规则。没有 Project Owner 确认的行为，写 `TBD`，不要自行补全。

### 1. 共同规则

- 输入文件要求
- Sheet 选择规则
- 表头识别规则
- 空值 / 重复值处理
- 导出文件命名与覆盖策略
- 失败时是否写部分结果

### 2. 格式统一规则

- 来源表与目标格式的对应关系
- 列顺序、列名、类型或填写要求
- 无法对齐时的处理
- 输出内容

### 3. 数据匹配规则

- 参与匹配的表
- 匹配键
- 匹配策略（只记录已确认策略，不发明新策略）
- 匹配成功 / 失败 / 多匹配的输出
- 输出内容

### 4. 校验与错误

- 哪些情况直接失败
- 哪些情况可继续并记录
- 需要回传给 UI 的错误信息

### 5. 规则验收

- 待回填可用样例文件验证的规则条目

## 与契约的关系

处理规则描述「结果应该是什么」。  
`docs/contracts.md` 描述 UI 如何触发这些处理、如何接收进度和错误。  
二者冲突时，先停，交给 Grok 判断是否超出已确认需求。
