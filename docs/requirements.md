# TabularStudio MVP 产品需求

- Status: Requirements baseline（已确认）
- Owner: Grok（Product Manager）
- Approver: Project Owner
- Last confirmed: 2026-09-02

本文是 MVP 需求基线。只记录已经确认的产品行为与范围。  
未确认细节不写入验收范围。本文不写实现算法、不写 C# 接口、不设计页面布局。

## 1. 文档定位

1. 产品范围以本文为准。
2. 页面布局、控件、状态和视觉细节由 Antigravity 写入 `docs/ui-spec.md`，不得反向扩大本文范围。
3. 格式统一与数据匹配的具体算法由 Codex 写入 `docs/processing-rules.md`，不得反向扩大本文范围。
4. 任何新能力必须先进入本文并经 Project Owner 确认，才能进入实现。

## 2. 产品定位

TabularStudio 是 Windows 本地桌面工具。

用户在本机选择 Excel 文件，完成表格处理后得到新的结果文件。整个过程完全离线，不依赖网络、账号、云服务或远程 API。

MVP 只包含两个功能：

1. 格式统一
2. 数据匹配

## 3. 已确认约束

| 项 | 已确认内容 |
| --- | --- |
| 运行环境 | Windows 本地桌面 |
| 语言 | C# |
| 运行时 | .NET 10 |

## 4. 文件格式

- 第一版只支持 `.xlsx`。
- `.xls`、`.csv` 不属于 MVP。
- 其它未确认文件格式不属于 MVP。

## 5. 格式统一

用户选择 1 个 `.xlsx` 文件，对选定工作表做格式统一，并生成新文件。

### 5.1 输入

- 输入 1 个 `.xlsx` 文件。
- 用户可以选择工作表。
- 用户可以指定表头所在行。
- 提供简单数据预览。
- 预览的具体呈现由 `docs/ui-spec.md` 维护，本文不规定布局。

### 5.2 用户可见处理能力

格式统一已经确认包括以下用户可见能力：

- 清理前后空格。
- 清理 Tab、换行、隐藏字符。
- 全角 / 半角统一。
- Unicode 标准化。
- 普通数字安全统一。
- 明确日期安全统一。
- 前导 0 编号优先保留。
- 长数字文本优先保留。
- 公式保持不变。
- 尽量保留现有业务格式，不重新套固定美化模板。

以上条目只描述产品行为。具体算法由 Codex 写入 `docs/processing-rules.md`，不在本文规定。

### 5.3 输出

- 处理完成后生成新文件。
- 默认文件名：`原文件名_格式统一.xlsx`。
- 默认保存在源文件所在目录。
- 允许用户修改保存位置。
- 禁止自动覆盖已有结果文件。
- 如果输出文件已经存在，提示用户重新选择文件名或明确确认覆盖该结果文件。
- 无论如何都禁止覆盖输入文件。

### 5.4 本功能非本文展开的部分

- 页面步骤、控件与视觉：`docs/ui-spec.md`
- 清理、统一、保留编号与日期等具体规则：`docs/processing-rules.md`

## 6. 数据匹配

用户选择主表和对照表，按已确认条件进行精确匹配，并把对照表字段带回主表，生成新的匹配结果文件。

### 6.1 输入

- 用户选择主表和对照表。
- 主表和对照表可以来自两个不同 `.xlsx`。
- 主表和对照表也可以是同一个 `.xlsx` 中的不同 Sheet。
- 主表、对照表均允许选择工作表。
- 主表、对照表均允许指定表头所在行。
- 主表、对照表均提供简单数据预览。
- 预览的具体呈现由 `docs/ui-spec.md` 维护，本文不规定布局。

### 6.2 匹配能力

- 支持 1～N 个匹配条件。
- 支持单字段匹配。
- 支持多字段联合精确匹配。
- 多个匹配条件之间固定为 AND。
- 所有条件全部符合才算匹配成功。
- 不支持模糊匹配。
- 用户可以选择一个或多个需要从对照表带回的字段。
- 返回字段追加到主表右侧。
- 返回字段与主表字段重名时，按 6.2.3 自动生成唯一列名。
- 主表原有行顺序不得因为匹配而改变。
- 主表原始字段不得因为匹配而改变。
- 唯一匹配才返回结果。
- 未匹配默认留空。
- 对照表重复匹配键按 6.2.2 处理。
- 匹配状态列按 6.2.1 处理。

### 6.2.1 匹配状态列

- 列名默认使用「匹配状态」。
- 匹配状态列默认启用，用户可以关闭。
- 状态包括：
  - 匹配成功
  - 未匹配
  - 重复
  - 匹配键为空

### 6.2.2 对照表重复匹配键

- 出现重复匹配键时，不中止整个匹配任务。
- 对应主表记录的返回字段留空。
- 如果启用了匹配状态列，则状态写「重复」。
- 其它记录继续正常处理。
- 不允许自动取第一条或最后一条。

### 6.2.3 返回字段与主表字段重名

按以下方式自动生成唯一列名：

- `字段名`
- 若已存在，则使用 `字段名_匹配`
- 若仍存在，则使用 `字段名_匹配2`
- 若仍存在，则使用 `字段名_匹配3`
- 依次递增

例如：主表已经存在「科室」，从对照表返回「科室」时，新字段使用「科室_匹配」。

### 6.3 匹配时的比较标准化

匹配过程中自动处理常见差异，包括：

- 空格
- 隐藏字符
- 全半角
- 文本 / 数字
- 明确日期

这些匹配标准化只用于比较，不修改主表和对照表的原始字段。

具体标准化算法由 Codex 写入 `docs/processing-rules.md`，不在本文规定。

### 6.4 输出

- 生成新的匹配结果文件。
- 默认文件名：`原文件名_匹配结果.xlsx`。原文件名指主表文件的原文件名。
- 默认保存在主表所在目录。
- 允许用户修改保存位置。
- 禁止自动覆盖已有结果文件。
- 如果输出文件已经存在，提示用户重新选择文件名或明确确认覆盖该结果文件。
- 无论如何都禁止覆盖输入文件。

### 6.5 本功能非本文展开的部分

- 页面步骤、控件与视觉：`docs/ui-spec.md`
- 比较标准化、唯一匹配判定、重复键处理的具体规则：`docs/processing-rules.md`

## 7. 两个功能之间的关系

- 格式统一后的结果可以继续作为数据匹配的主表。
- 用户也可以跳过格式统一，直接进行数据匹配。

## 8. UI 边界

- UI 页面方案已经确认。
- 本文只记录用户可见能力。
- 具体布局、控件、状态和视觉细节由 Antigravity 维护 `docs/ui-spec.md`。
- 本文不重新设计页面。

## 9. MVP 非目标

以下内容明确不在当前 MVP 内：

- AI
- Web 应用、网站、浏览器插件
- 后端服务、REST / gRPC API
- 数据库
- 云服务、在线账号、云同步、远程文件存储
- 模糊匹配
- 第三个产品功能
- `.xls`、`.csv` 及其它未确认文件格式
- 未在本文出现的智能分析、报表看板、权限系统、多用户协作
- 为格式统一重新套固定美化模板

## 11. 验收原则

MVP 验收以本文已确认行为为准，并在 Windows 本地、完全离线、仅针对 `.xlsx` 验证：

1. 格式统一：能选择文件、工作表和表头行，能预览，能按已确认能力处理，能生成新文件且不覆盖输入文件。
2. 数据匹配：能选择主表与对照表（两个文件或同一文件不同 Sheet），能选择工作表和表头行，能预览，能按已确认匹配规则处理，能生成新文件且不覆盖输入文件。
3. 格式统一的结果可作为数据匹配主表；也可以跳过格式统一直接匹配。

页面验收细节以 `docs/ui-spec.md` 为准。  
处理对错以 `docs/processing-rules.md` 为准。  
上述两份文档在补齐前，不得把未写入本文的细节当成已确认需求。
