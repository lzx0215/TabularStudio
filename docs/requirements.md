## 2. 产品定位

TabularStudio 是 Windows 本地桌面工具。

用户在本机选择表格文件，完成处理后得到新的结果文件。整个过程完全离线，不依赖网络、账号、云服务或远程 API。

产品只包含两个功能：

1. 格式统一
2. 数据匹配

## 4. 文件格式

- 已确认支持 `.xlsx`、`.xls`、`.csv`。
- 输入是哪种已确认格式，结果文件就按该格式写回。
- `.xlsx` 输入生成 `.xlsx` 结果；`.xls` 输入生成 `.xls` 结果；`.csv` 输入生成 `.csv` 结果。
- 不允许把一种已确认格式自动转成另一种格式。
- `.csv` 没有工作表，不提供工作表选择。「同一文件不同 Sheet」只适用于 `.xlsx` 与 `.xls`。
- 其它未确认文件格式不属于当前范围。

## 5. 格式统一

用户选择 1 个或多个已确认格式的表格文件，对每个文件的选定工作表做格式统一，并分别生成新文件。

### 5.1 输入

- 支持选择 1 个文件，也支持一次选择多个文件。
- 每个文件必须是 `.xlsx`、`.xls` 或 `.csv`。
- 一次批量中允许混合已确认格式。
- `.xlsx` 与 `.xls`：每个文件可以独立选择工作表。
- `.csv`：不选择工作表，直接处理该文件。
- 每个文件可以独立指定表头所在行。
- 每个已选文件提供简单数据预览。
- 预览的具体呈现由 `docs/ui-spec.md` 维护，本文不规定布局。

### 5.2 用户可见处理能力

格式统一已经确认包括以下用户可见能力：

- 清理前后空格。
- 清理 Tab、换行、隐藏字符。
- 全角 / 半角统一。
- Unicode 标准化。
- 普通数字安全统一。
- 明确日期安全统一。
- 前导 0 编号优先保留。
- 长数字文本优先保留。
- 公式保持不变。
- 尽量保留现有业务格式，不重新套固定美化模板。

以上条目只描述产品行为。具体算法由 Codex 写入 `docs/processing-rules.md`，不在本文规定。

### 5.2.1 规则默认与开关

- 「清理前后空格」「清理 Tab、换行、隐藏字符」「全角 / 半角统一」「Unicode 标准化」「普通数字安全统一」默认不启用，用户按需勾选。
- 「明确日期安全统一」默认不启用。日期/时间类型默认不处理；只有用户勾选后才处理。
- 「前导 0 编号优先保留」「长数字文本优先保留」始终启用，用户不可关闭。
- 「公式保持不变」以及「不重新套固定美化模板」始终生效。
- 一次批量中的全部文件使用同一套规则勾选结果。

### 5.2.2 批量处理

- 只做格式统一批量。数据匹配不支持一次处理多个主表或对照表组合。
- 批量时全部文件使用同一套标准化规则。
- 每个文件可以有不同的工作表名。
- 每个文件可以有不同的表头行。
- 每个输入文件各生成一个结果文件，不把多个文件合并成一个结果。
- 某个文件失败时，其余文件继续处理。
- 全部文件处理结束后，必须能看到每个文件成功或失败；失败文件给出失败原因。
- 不得因为其中一个文件失败而回滚已经成功写出的其它结果文件。

### 5.3 输出

- 处理完成后生成新文件；批量时每个成功处理的输入文件对应一个结果文件。
- 默认文件名：`原文件名_格式统一` + 与该输入文件相同的扩展名。
  - 例如：`业务流水.xlsx` → `业务流水_格式统一.xlsx`
  - 例如：`业务流水.xls` → `业务流水_格式统一.xls`
  - 例如：`业务流水.csv` → `业务流水_格式统一.csv`
- 用户尚未指定过输出目录时，默认保存在该输入文件所在目录。
- 允许用户修改保存位置。
- 记住用户最近一次指定的输出目录。该记忆保存在本机，再次启动后仍然有效。
- 用户指定过输出目录之后，后续单文件和批量处理都默认使用该目录；最末端文件名仍按上面的规则自动生成，不沿用上一次的完整文件名。
- 切换输入文件时，不把输出路径整段锁成上一次的完整路径。
- 若记住的输出目录不存在，则该次回退到当前输入文件所在目录。
- 禁止自动覆盖已有结果文件。
- 如果某个输出文件已经存在，提示用户重新选择文件名或明确确认覆盖该结果文件。
- 无论如何都禁止覆盖输入文件。

### 5.4 本功能非本文展开的部分

- 页面步骤、控件与视觉：`docs/ui-spec.md`
- 清理、统一、保留编号与日期等具体规则：`docs/processing-rules.md`
- `.xls` / `.csv` 的本地读写方案：`docs/decisions/` 与 `docs/architecture.md`

## 6. 数据匹配

用户选择主表和对照表，按已确认条件进行精确匹配，并把对照表字段带回主表，生成新的匹配结果文件。

### 6.1 输入

- 用户选择主表和对照表。
- 主表和对照表可以来自两个不同的已确认格式文件。
- 主表和对照表也可以是同一个 `.xlsx` 或同一个 `.xls` 中的不同 Sheet。
- `.csv` 没有工作表，不能作为「同一文件不同 Sheet」的来源。
- 主表、对照表若为 `.xlsx` 或 `.xls`，均允许选择工作表。
- 主表、对照表均允许指定表头所在行。
- 主表、对照表均提供简单数据预览。
- 数据匹配一次只处理一组主表与对照表，不支持批量多组匹配。
- 预览的具体呈现由 `docs/ui-spec.md` 维护，本文不规定布局。

### 6.2 匹配能力

- 支持 1～N 个匹配条件。
- 支持单字段匹配。
- 支持多字段联合精确匹配。
- 多个匹配条件之间固定为 AND。
- 所有条件全部符合才算匹配成功。
- 不支持模糊匹配。
- 用户可以选择一个或多个需要从对照表带回的字段。
- 返回字段追加到主表右侧。
- 返回字段与主表字段重名时，按 6.2.3 自动生成唯一列名。
- 主表原有行顺序不得因为匹配而改变。
- 主表原始字段不得因为匹配而改变。
- 唯一匹配才返回结果。
- 未匹配默认留空。
- 对照表重复匹配键按 6.2.2 处理。
- 匹配状态列按 6.2.1 处理。

### 6.2.1 匹配状态列

- 列名默认使用「匹配状态」。
- 匹配状态列默认启用，用户可以关闭。
- 状态包括：
  - 匹配成功
  - 未匹配
  - 重复
  - 匹配键为空
  - 未参与匹配（启用 6.2.4 的主表筛选且该行不满足条件时）

### 6.2.2 对照表重复匹配键

- 出现重复匹配键时，不中止整个匹配任务。
- 对应主表记录的返回字段留空。
- 如果启用了匹配状态列，则状态写「重复」。
- 其它记录继续正常处理。
- 不允许自动取第一条或最后一条。

### 6.2.3 返回字段与主表字段重名

按以下方式自动生成唯一列名：

- `字段名`
- 若已存在，则使用 `字段名_匹配`
- 若仍存在，则使用 `字段名_匹配2`
- 若仍存在，则使用 `字段名_匹配3`
- 依次递增

例如：主表已经存在「科室」，从对照表返回「科室」时，新字段使用「科室_匹配」。

### 6.2.4 主表条件筛选匹配（2026-09-08）

- 可选地指定一个主表列和一个非空比较值；仅该列值等于指定值的主表行参与匹配。例如：主表 A 列等于「是」时，才使用主表 B、C、D 列分别与对照表选定三列做联合精确匹配。
- 主表筛选列、比较值、两表匹配列和返回字段由用户选择，不固定为某个列字母或字段名。
- 筛选默认关闭；关闭时保持现有匹配行为。
- 筛选仅支持单列等于一个指定值。不增加 OR、多个筛选条件、表达式、模糊匹配或数据匹配批量。
- 满足筛选条件后，沿用 6.2 的 AND、唯一匹配、重复键、空匹配键、返回字段及列名避让规则。
- 不满足筛选条件的行仍保留在输出主表中，返回字段留空；启用匹配状态列时写「未参与匹配」。不得把这些行算作未匹配、重复或匹配键为空。
- 结果统计包含未参与匹配行数，且总行数等于匹配成功、未匹配、重复、匹配键为空、未参与匹配五类行数之和。
- 筛选不改写主表原始值，不删除或重排行；返回字段仍追加在主表右侧。
- 筛选比较沿用匹配比较的标准化开关；具体安全比较细节由处理规则与契约在实现前同步。
- 不满足条件的行保留、状态为「未参与匹配」是本次采用的保守默认；如 Owner 改为过滤掉行，应先更新本节再实施。

### 6.3 匹配时的比较标准化

匹配过程中自动处理常见差异，包括：

- 空格
- 隐藏字符
- 全半角
- 文本 / 数字
- 明确日期

这些匹配标准化只用于比较，不修改主表和对照表的原始字段。

具体标准化算法由 Codex 写入 `docs/processing-rules.md`，不在本文规定。

本节是匹配比较用的标准化，不等于格式统一会改写日期/时间。格式统一是否处理日期/时间，以 5.2.1 为准。

### 6.4 输出

- 生成新的匹配结果文件。
- 默认文件名：`原文件名_匹配结果` + 与主表输入文件相同的扩展名。原文件名指主表文件的原文件名。
- 输出格式与主表输入格式相同。
- 用户尚未指定过输出目录时，默认保存在主表所在目录。
- 允许用户修改保存位置。
- 与格式统一共用本机记住的最近一次输出目录。用户指定过输出目录之后，数据匹配也默认使用该目录；最末端文件名仍按上面的规则自动生成。
- 切换主表文件时，不把输出路径整段锁成上一次的完整路径。
- 若记住的输出目录不存在，则该次回退到当前主表所在目录。
- 禁止自动覆盖已有结果文件。
- 如果输出文件已经存在，提示用户重新选择文件名或明确确认覆盖该结果文件。
- 无论如何都禁止覆盖输入文件。

## 11. 验收原则

验收以本文已确认行为为准，并在 Windows 本地、完全离线、针对 `.xlsx`、`.xls`、`.csv` 验证：

1. 格式统一：能选择 1 个或多个已确认格式文件；`.xlsx` / `.xls` 能选工作表，`.csv` 不选工作表；能按文件指定表头行；能预览；可选规则默认不启用；日期/时间默认不处理；保护项始终启用；能按原格式各生成新文件且不覆盖输入文件。
2. 格式统一批量：同一套规则；不同文件可有不同工作表名和表头行；各生成一个结果；某个文件失败时其余继续，并展示每个文件的成功或失败。
3. 数据匹配：能选择主表与对照表（两个文件，或同一个 `.xlsx` / `.xls` 的不同 Sheet）；能选择工作表（不适用 `.csv`）和表头行；能预览；能按已确认匹配规则处理；结果按主表原格式写回且不覆盖输入文件。数据匹配一次只处理一组。
4. 输出目录：用户指定过输出目录后，换文件或再次启动仍默认使用该目录；最末端文件名仍自动生成。
5. 格式统一的结果可作为数据匹配主表；也可以跳过格式统一直接匹配。

页面验收细节以 `docs/ui-spec.md` 为准。  
处理对错以 `docs/processing-rules.md` 为准。

## 14. 2026-09-08 批量使用反馈（Issue #52，Owner 已确认）

- 格式统一文件操作为添加文件、修改勾选文件、移除勾选文件。添加支持一次多选和多次追加，拖拽也追加，重复文件不重复加入。
- 修改针对勾选项逐一选择替代文件，取消保留该项；替换重新选择/加载工作表与表头，不继承旧文件的失效配置。移除仅作用列表，不删除磁盘文件。
- 每个文件都可切换预览，当前预览文件明确可见；勾选用于修改/移除，与查看预览区分。
- 转化失败在执行结果区直接显示失败文件、原因和可用错误位置；无法定位具体行/列时不编造位置。
- 可选规则仍默认关闭；至少选中一项可选规则才能开始格式统一，未选时禁用开始并说明原因。保护项不算可选规则。
